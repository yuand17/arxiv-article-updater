# 来源、分类与调度

## 固定来源

| 来源 | 默认节奏 | 行为 |
|---|---:|---|
| arXiv | 官方工作日发布 | 从上次成功边界回退一天，按提交时间倒序分页读取；每次网络请求至少间隔 3 秒。瞬时 TLS、连接、408、429 和 5xx 最多尝试 3 次。 |
| SciRate | 3 天 | 读取三日榜前 50；成功后清除已经离开榜单的旧热门标记。手动更新可打开专用 Chrome 完成真人验证。 |
| Google Scholar | 7 天 | 仅在 SerpAPI 已启用且有足够额度时运行。后端固定按发表时间读取每位作者最近 10 篇，并跨作者去重。 |
| 重点期刊 | 1 天 | 同步 8 本内置期刊中已开启的订阅；一本失败不影响其他期刊和已保存数据。手动更新 Science 两刊遇到 Cloudflare 时可打开专用 Chrome 完成人工验证。 |
| 偏好画像 | 7 天且有新互动 | DeepSeek 可用时重建画像；不可用时保留已有画像并继续本地推荐。 |
| 三天精选 | 3 天 | 所有到期来源先独立更新，再从严格三日窗口生成一个批次。 |
| 数据清理 | 每个成功三日批次后 | 删除超过 9 天且无互动、未被最近三个批次保护的论文。 |

## 内置重点期刊

当前版本固定内置以下 8 本期刊，不开放自定义期刊发现入口：

1. Nature
2. Nature Physics
3. Nature Communications
4. Science
5. Science Advances
6. Physical Review Letters
7. Physical Review X
8. PRX Quantum

每本期刊有独立开关。官方 RSS 或 Atom 决定本次文章集合；Crossref 只按 DOI 补作者、摘要、日期和主题，不会单独扩大文章集合。Nature/AAAS/APS 的官方入口或 Crossref 失败时，程序保留上次成功数据，并在设置页显示可操作的重试提示。

设置页手动更新 Science 或 Science Advances 时，如果官方 feed 返回 Cloudflare challenge，程序会打开 `data/chrome/journals/` 下的专用 Chrome 档案并等待真人验证，最长 5 分钟。定时更新不会弹窗或绕过验证，只记录安全错误、保留上次成功数据并稍后重试。

Lantern 使用 Fake-IP DNS 时，期刊网络层会针对实际出版社主机探测 `198.18.0.0/15`，通过 DoH 获得真实 IPv4，并绑定物理网卡请求。检测到 Fake-IP 却找不到物理接口时会明确失败，不会修改 Lantern、VPN/TUN 或系统路由。

## 期刊分类

期刊条目按固定顺序处理：

1. 规范标题、作者、摘要、DOI、链接和日期并去重。
2. 优先使用出版社结构化类型，排除新闻、评论、社论、综述、勘误和撤稿等非原创内容。
3. PRL 原创 Letter 保留；普通来信只有得到原创研究证据才保留。
4. 物理专业期刊以期刊范围作为强证据；综合期刊必须从主题、标题或摘要获得明确物理证据。
5. 不确定的综合期刊条目默认排除，并在 `seen_source_items` 保存机器可读原因。

摘要只来自来源本身、已明确知道 ID 的 arXiv 元数据、出版社元数据或本地 DOI/arXiv ID 精确关联。无法可靠取得时显示“暂无摘要”。

## 三天精选

候选必须满足 `published_at` 或 `discovered_at` 位于最近三天，并排除“不感兴趣”和最近 30 天内未实质更新的已推荐论文。本地 BM25 对标题赋予更高权重，并结合近期性、重点作者、SciRate、期刊和来源多样性生成短名单。

DeepSeek 按最多 50 篇分组精排；任何失败分组单独回退到本地分数。最终只保存设置中的目标篇数，候选不足时不从第四天或更早论文补齐。

## 成功、部分成功与重试

- arXiv、SciRate、Scholar 或全部期刊订阅失败时，该来源运行记为失败，并按失败退避计划重试。
- 期刊只有部分订阅失败时，运行记为成功并附带“部分期刊未更新”提示；成功订阅正常提交，失败订阅保留上次成功边界。
- 来源错误在数据库中保留脱敏技术分类；普通页面只显示友好提示，避免把底层 TLS 或 Python 异常直接暴露给使用者。
